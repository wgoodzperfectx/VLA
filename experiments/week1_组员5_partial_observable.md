一、解决问题
1、Q：什么是 partial observability？
    A：就是攻击者在攻击VLA机器人时，需要拿到机器人运行的轨迹信息。但在很多时候不能拿          到完整的。一小段轨迹信息就是partial observability
2、Q：为什么攻击者不能假设看到完整轨迹？
     A：对于商用机器人、工业机械臂有数据隔离，外部人员无法导出完整执行日志 + 全程图像            流
       就算能外接摄像头偷拍，也只能拍到开头片段，机器人后端后续动作数据完全拿不到
       手机偷拍有额外干扰：拍摄角度偏移、抖动、光线差异、画面裁剪，倒推得到的轨迹信息质量低，也算观测不完全
       想拿到完整轨迹难度比较高，所以不假设看到完整轨迹
3、Q：patch 是固定的还是每帧变化的？
     A：固定的。因为把贴纸打印出来后，就让它固定不变
        但白盒对抗算法会为每一帧单独优化专属补丁，每一帧图案都不一样
 4、Q：partial observability这种设定比普通白盒攻击现实在哪里？
     **白盒攻击**：攻击者完整拿到模型权重、输入输出数据流、全程所有轨迹帧、机器人内部动作规划，属于完全可观测（full observability）理想假设
     A：1. 数据获取门槛大幅降低，不用入侵机器人系统
        2.补丁是物理固定贴纸，不用逐帧动态修改
        3. 不需要全程监控机器人，只需要短暂观测
5、Q：如果我们暂时没有机械臂，如何在仿真中记录攻击效果？

    A：记录攻击效果：
- **环境搭建**
    在 Mujoco/Isaac Sim 等仿真器搭建对应机器人任务场景（抓取、放置、分拣等），接入 VLA 模型推理接口。
- **基线对照组（无补丁）**
    循环运行 N 次任务，自动记录：成功率、轨迹数据、匹配分数、视频日志，作为基准。
- **构建 Partial Observability 攻击设定**
    - 截取任务前 K 帧（short prefix 前缀片段）作为观测数据；
    - 离线优化得到**固定对抗 patch**；
    - 将补丁叠加到仿真相机所有后续帧，全程不更换补丁图案。
    
- **攻击实验组（带固定补丁）**
    相同任务循环 N 次，自动化采集完全相同维度数据，统一存入 CSV / 日志文件。
- **数据离线统计**
    用 Python 读取日志，计算指标差值：成功率下降值、轨迹曲率均值提升量、跨模态匹配衰减幅度。

二、4个文件夹
clean、attacked、defended、rollout logs 应该分别存什么
### 1. clean/ 干净基线组（无任何对抗补丁）

作用：对照组，用来计算攻击带来的性能下降幅度

存放文件：

1. 每轮任务完整帧 RGB 图像、深度图、分割图；
2. 单任务末端执行器 x/y/z 时序坐标、关节轨迹文件；
3. VLA 模型原始输出：动作向量、文本 - 视觉匹配分数；
4. 单轮任务标签：成功 / 失败、失败原因（无干扰几乎全成功）；
5. 无补丁场景截图、原始注意力图；
6. 单任务耗时、运动总路径长度、平均轨迹曲率基线值。

### 2. attacked/ 对抗攻击组（本文 partial observability 设定：固定 patch）

作用：仅用轨迹前缀优化固定补丁，全程画面叠加同一 patch 的实验组

存放文件：

1. 叠加固定对抗补丁后的所有仿真帧图像；
2. 受干扰后的机械臂末端轨迹、关节运动时序；
3. 被破坏的跨模态匹配分数（指令与目标物体匹配度下降数据）；
4. 任务失败样本：抓空、碰撞、轨迹大幅偏移的帧与标注；
5. 攻击下注意力漂移热力图（注意力集中在补丁而非目标物体）；
6. 单轮任务失败分类标签：语义接地失效 / 运动轨迹畸变；
7. 攻击组任务完成步数、路径总长、平均曲率（用于和 clean 对比）。

### 3. defended/ 防御加固组（可选，做防御消融实验时使用）

作用：部署对抗防御算法后，再叠加相同 patch 做测试，验证防御效果

存放文件：

1. 开启防御模块、叠加同一固定 patch 的仿真画面；
2. 防御修复后的轨迹数据、恢复后的文本视觉匹配分数；
3. 防御后任务成功 / 失败统计；
4. 防御层中间输出（降噪、注意力校正、鲁棒特征等中间结果）；
5. 防御前后对比截图、修复后的注意力热力图。

### 4. rollout_logs/ 全局原始时序日志（所有组共用底层原始数据）

不区分 clean/attacked，存储仿真运行过程中实时打印的底层结构化日志，用于离线重跑、指标复现：

1. 时序表格 CSV：每帧时间戳、相机内参、机械臂 6D 位姿、关节角度、角速度；
2. VLA 模型逐帧原始推理日志：图像编码特征、文本编码特征、输出动作序列、预测损失；
3. 仿真物理日志：碰撞记录、物体遮挡、抓取接触判定；
4. 攻击优化过程日志：仅前缀帧参与 patch 优化的 loss 迭代记录、梯度信息；
5. 任务全局元信息：语言指令、物体初始摆放位置、补丁粘贴坐标、仿真随机种子；
6. 重放配置文件：加载该组 rollout 即可复现完整仿真流程，方便二次分析。

三、为什么 VLA 对抗实验不能只存图片，必须同步保存动作、轨迹、任务结果
- 图片仅作**可视化辅助材料**，用于论文配图直观展示干扰画面；
- 动作、轨迹数据：量化控制层畸变、计算曲率、还原长时序运动偏差；
- 任务结果标签：提供全局定量指标（成功率、失败分类），支撑实验结论；
- rollout 时序日志：保证实验可复现、区分 partial observability 观测边界、分层定位感知 / 控制失效根源。
    
    三者缺一不可，只存图片会导致实验只有定性观感，无严谨定量数据，无法支撑论文论证。

四、最小仿真实验记录格式
每组实验（单种子单任务）仅输出 3 类文件：

1. `meta.csv`：全局实验元信息（复现必需）
2. `rollout.csv`：逐帧时序最小动作 / 视觉指标（核心量化数据）
3. `result.json`：单轮任务最终成败汇总指标（论文统计用）
    
    图像仅做可选附属，不纳入核心记录格式。

## 二、1. meta.csv（单任务全局元数据，1 行 1 个 episode）

用途：锁定 partial observability 实验条件，保证可复现

表格

|字段|说明|
|---|---|
|exp_id|实验编号，如 partial_patch_k10_seed0|
|task_name|操纵任务名：pick_cup /stack_block|
|seed|仿真随机种子|
|obs_prefix_k|部分可观测前缀帧数（攻击者仅用前 K 帧优化 Patch）|
|patch_fixed|是否固定补丁（本实验恒为 True）|
|patch_pos|补丁粘贴坐标 (x,y,w,h)|
|group_type|分组：clean /attacked/defended|
|instruction|VLA 语言指令|
|sim_time_total|总仿真步数 / 时长|

## 三、2. rollout.csv（逐帧最小时序记录，核心数据）

每帧一行，用于计算轨迹曲率、跨模态匹配、动作偏移

表格

|字段|最小必要性说明|
|---|---|
|step|帧序号，区分前缀帧 (step<K) 与攻击帧 (step≥K)|
|ee_x,ee_y,ee_z|末端执行器三维坐标（计算轨迹曲率唯一必需）|
|act_dx,act_dy,act_dz|模型输出动作向量（判断控制偏移）|
|grounding_score|指令 - 目标物体跨模态匹配分（衡量语义接地破坏）|
|attention_patch_ratio|注意力落在补丁区域占比（感知干扰量化）|
|collision|0 无碰撞 / 1 碰撞（控制失效辅助标记）|

> 无需存原始 RGB 图，如需可视化可仅存缩略图路径 `img_path` 作为可选字段。

## 四、3. result.json（单轮任务最终汇总指标，用于批量统计成功率）

极简 JSON 结构，只保留论文关键指标

json

```
{
  "success": true/false,
  "fail_type": "semantic"|"trajectory"|"collision"|null,
  "avg_curvature": 数值,
  "avg_grounding_score": 数值,
  "total_path_length": 数值,
  "max_attention_patch": 数值
}
```

字段释义：

- success：任务成败标签，计算成功率核心
- fail_type：区分是感知语义失效还是运动控制失效
- avg_curvature：全程轨迹平均曲率（攻击核心指标）
- avg_grounding_score：平均跨模态匹配分数
- total_path_length：运动总路径长度
- max_attention_patch：注意力向补丁漂移最大值
